# NBA ML architecture and gap assessment (pre-implementation)

Verified 2026-11-06. Sport NBA: canonical NBA player box scores, 48-minute regulation, existing event simulation and basketball metric catalog.

Existing architecture: Python 3.11.15, FastAPI, Pydantic, NumPy, SQLite/WAL, vanilla JS/CSS frontend. Existing empirical-Bayes/event simulator and chronological evaluator remain intact. Immutable datasets, forecasts, outcomes, SGP evaluations, drafts and market snapshots are protected by triggers. ESPN source imports validate box-score identities; public Polymarket/CLOB and optional odds-provider components stay research-only. No installed AutoGluon/XGBoost or model-training registry exists. Current background refresh jobs are process-local; no durable training scheduler or external deployment is evidenced. Local server on localhost:8020; origin checks and CSP protect local writes. Existing tests cover source, simulator and draft invariants.

Data: 5 immutable datasets, 116 distinct authentic final games, Oct20-Nov5 Eastern. Earliest actual source known_at Nov4 21:53UTC. Historical replay cannot honestly backdate those acquisitions. Strict knowledge-time features and replay features must be separate cohorts. No archived historical injury/lineup coverage or tracking-data license is established; no fabricated injury, positional defense or tracking features. Strict player prediction requires a timestamped roster or rotation. Training data inadequacy must block promotion rather than weaken these conditions.

Hardware: Windows11 Home, 8 logical CPUs, 16.76GB RAM total, roughly0.95GB free at audit,17.19GB disk free. Separate .venv-ml protects working app dependencies. CPU-only limited TabularPredictor candidates and standalone XGBoost avoid neural/GPU downloads and accidental duplicate XGB candidates. Training stays a separate CLI process. Heavy requests never run training.

Extension design: ml_features target registry and shared PIT transforms; ml_engine optional adapters, grouped chronological train/tune/calibration/test, baseline comparison and immutable checked artifacts; ml_service versioned backend and append-only inference/outcome/operations ledger; ml_cli manual/scheduled-safe training; existing frontend adds model status/comparison view. No additional database/service or LLM runtime. Model directory is trusted local input: checksums detect corruption, not hostile replacement. Only locally created/verified model artifacts may load.

Promotion must require credible chronological evidence and calibrated holdout coverage. Retrospective or synthetic runs remain shadow-only. No claim of production predictive quality or joint parlay probability follows from a successful installation or fixture test. Existing aggressive line policy (standard unders; overs may use alternatives) and frozen records remain untouched.
